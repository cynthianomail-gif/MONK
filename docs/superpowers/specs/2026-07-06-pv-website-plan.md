## 0. 定位

- **目標受眾**：AI 競賽評審＋一般玩家。重點是「內容量＋完成度＋美術統一性」，不是賣課金。
- **一句話賣點（logline，草案）**：「眾神開公司統治城市，一個和尚負責把祂們超渡掉。」
- **無 Steam**：PV 結尾與官網 CTA 一律不導 wishlist，改導 demo／參賽作品資訊。
- 參考基準：Persona 5 / Metaphor（UI 即品牌、beat-sync 剪輯）、人中之龍 8（正經↔荒謬反差）、FF7 Rebirth（大招當高潮）、Clair Obscur: E33（一句話世界觀 hook）、Sea of Stars / Hades（獨立遊戲官網＝極簡＋press kit 齊全）。
- 鐵律：實機畫面佔比 ≥50%、前 5 秒定生死、剪輯點踩音樂節拍。

## 3. 生成管線：關鍵幀先審制＋尾幀接龍（C 桶核心制度）

### 3.1 兩階段流程

**階段一：關鍵幀批次（靜圖，便宜）→ 使用者逐張確認 → 才進階段二。**
方向錯誤全部擋在靜圖階段，一張圖的成本 vs 一支影片的成本差一個數量級。
關鍵幀不過＝改圖重出，**禁止**「圖差不多就先生影片看看」。

**階段二：影片生成（首尾幀模式優先）。**
- 有明確首、尾構圖的鏡頭 → 用首尾幀（first/last frame）模式，兩端都被已審核的圖錨定。
- 連續序列的段與段之間 → **尾幀接龍**：擷取上一段輸出影片的最後一幀 → Magnific upscale/修復 → 當下一段的首幀。

### 3.2 尾幀接龍的適用範圍與防劣化規則

**只用在連續運鏡序列內**（開場俯瞰、收尾 logo 過渡）。蒙太奇硬切段（27–52s）**禁止接龍**——那些 clip 本該是不同場景硬切，接龍沒有意義還會讓色調黏連。

防劣化三規則（接龍必守）：
1. **尾幀先修復再餵**：擷取的尾幀必過 Magnific upscale／清晰化，消除動態模糊與細節流失後才能當下一段首幀。
2. **鏈長上限 2–3 段**：超過就回到「乾淨關鍵幀」重新錨定（重畫一張首幀），不讓劣化累積。
3. **逐段 QC 尾幀**：每段生成後先檢查尾幀（構圖偏移／色偏／臉部崩壞），不過＝重生成**該段**，不准硬接下去。

## 4. PV 製程（照既有制度）

1. 素材盤點（27 支過場源檔位置、可用實錄場景清單）→ `_tracking.md` 開檔
2. shot-by-shot 分鏡表落檔（本 spec 第 3.4 節為生成部分；實錄部分開工時補齊每鏡秒數）
3. 實錄批次（免費先做）
4. **關鍵幀批次 KF-01～07 → 使用者逐張確認**（第 3.3 節）
5. 影片樣本 S1a → 使用者確認風格 → 其餘鏡頭放量（含接龍段，守第 3.2 節防劣化規則）
6. 逐段 QC（subagent 看圖回報：檔名｜通過/不通過｜一句話原因；接龍段加驗尾幀）
7. 音樂＋音效生成（見第 5 節）
8. ffmpeg 組裝、beat-sync 對點、混音 → 1080p30 成片 → 4K upscale
9. fresh review 驗收（對照分鏡表逐鏡核對）

## 5. 音訊

- 音樂：Magnific 音樂生成 60s 一曲。結構要求：和風打擊底＋電子霓虹層；38s 處「收掉→變調」（進小遊戲段）；52s 處「爆→急停」（進收尾）。
- 音效：木魚（開場×3＋收尾×1）、鐘。單獨生成後 ffmpeg 混音。

1. 素材盤點＋實錄分鏡補齊 → `_tracking.md`
